# Threat model

Untrusted model output, caller-supplied risk, role spoofing and unknown tools are primary threats. Policy and principal must come from authenticated, trusted host configuration; the model only proposes a tool. Invalid policies and requests deny. Critical risk denies; medium/high require review. Deny wins over review and allow. The trusted-host gateway implements registered handler execution, scope-bound single-use approval consumption and pre-execution audit. Optional authenticated local persistence preserves consumption across ordinary restarts; it is not distributed or resistant to restoration of older authenticated snapshots. Handler failure or invalid output does not imply rollback of side effects. See persistence.md and acceptance.md for tested boundaries. CLI fixtures are not trusted identities. Do not use as a standalone enforcement boundary. Restrict access to policy files and gate every side effect in the host. Prompt-injection detection is not a security guarantee. The API accepts plain JSON data, not executable objects or proxies. CLI accepts trusted local file paths only; input is limited to 64 KiB per file and regular files.
